# craft-common 2.0.0 发布准备

正式版本号为`2.0.0`，当前状态是**待发布**。frontend-craft继续使用未发布的`3.0.0`，backend-craft继续使用未发布的`1.0.0`；两者只更新精确公共依赖及生成内容。本步骤不创建Git提交/标签，不推送或执行npm发布。

变更说明见[英文](../../CHANGELOG.md)与[简体中文](../../CHANGELOG.zh-CN.md)。公共入口21个，前端74个，后端42个；版本号形式不表示公开源已经可用。

## 本地生成与核验

在common源码仓执行既有命令：

```sh
pnpm run sync:methods
pnpm run sync:methods -- --check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm run pack:skills
```

先创建空的产物目录`npm-packages/releases/2.0.0`，再执行：

```sh
pnpm exec npm pack --pack-destination npm-packages/releases/2.0.0
```

使用该npm归档，不改用pnpm 12.4.1的pack：后者排除嵌套pnpm-lock.yaml。实际解包检查21个双语入口、方法、声明、许可证、两份changelog、此发布说明和示例锁；示例不含node_modules、编译或运行缓存。对实际tgz记录字节数、SHA512/SRI，保存在本地独立发布清单中，避免把自身摘要嵌入被摘要的包。

可对同一归档执行只读发布预演，预演成功不代表已上传或公开可下载：

```sh
npm publish npm-packages/releases/2.0.0/bovinphang-craft-common-2.0.0.tgz --dry-run --access public --json
```

两产品须消费这一份实际归档，更新精确`2.0.0`依赖与真实SRI，再运行`sync:common`/`check:common`、类型/构建及相关内容、安装和分发检查。公共独立Skill包版本同为2.0.0；前后端领域包仍跟随各自3.0.0/1.0.0。临时本地源和精确版本例外只用于联调，结束后恢复原策略并移除开发服务地址，不修改全局registry或关闭供应链核验。

正式版本归档一经作为本轮发布产物交付，就以清单中的字节为准；后续源码改动须重新准备并协调消费者SRI，不能默默替换已验证产物，更不能覆盖已发布版本。

## 获得发布授权后的操作

以下命令仅供维护者在获得独立发布授权后执行，本次不执行：

```sh
npm publish npm-packages/releases/2.0.0/bovinphang-craft-common-2.0.0.tgz --access public
npm view @bovinphang/craft-common@2.0.0 dist.integrity
```

1. 发布前重新确认2.0.0未被占用、账号/组织权限及npm认证要求；不要打印凭据。
2. 将公开`dist.integrity`与本地发布清单、两产品锁中的SRI比对，必须完全一致。
3. 保持原供应链策略，在干净环境使用公开源分别验证两产品的`pnpm install --frozen-lockfile`及已有门禁。等待策略窗口时如实记录，不将本地缓存或临时源成功当公开安装成功。
4. 只有公共包发布及公开消费验证完成后，才考虑另行发布两产品。当前不提升两产品版本号，也不因common就绪自动发布它们。
5. 实际发布后再将changelog的“未发布”标记替换为真实发布日期，并记录Git标签/远端发布结果；本次准备不伪造这些状态。

## 迁移与验证边界

版本、语言或内容摘要不同的公共消费者不能混装。先备份编辑，用旧产品CLI退出全部旧公共引用，处理保留文件，再安装两份匹配产品；不自动升级另一产品或强制接管未知文件。同一宿主的CLI与原生渠道继续互斥，双原生产品去重不属于本次承诺。

已有开发版验收记录保留其原版本、摘要和执行日期；本次正式版清单单独记录版本/SRI、实际命令及未运行项。GUI/签名、真实数据库/生产鉴权、浏览器E2E、全部最低工具版本及公开发布不因版本提升而自动获得验证。
