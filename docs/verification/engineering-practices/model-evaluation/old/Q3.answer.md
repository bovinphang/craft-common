建议保留纯 C ABI、现有错误码和禁用异常的构建策略。直接把所有入参包装成 `shared_ptr` 会擅自取得所有权，可能误释放宿主内存；开启异常、迁移接口也超出了本次修复范围。

1. **明确所有权与释放契约。** 宿主传入的指针始终借用，插件不得 `free/delete`，也不得用默认删除器的智能指针接管。默认借用仅持续到调用返回；若需异步使用，应复制到插件拥有的内存，或明确宿主保证存活的期限。插件分配的结果必须通过插件导出的配对释放函数销毁，并使用原分配器及其上下文；宿主不能直接释放，相关资源释放前不能卸载插件。

2. **最小修复失败路径。** 在 C 实现中将局部资源初始化为空，所有提前返回汇入明确的清理路径，按获取的逆序仅释放已成功获取的资源。C++ 实现可用不分配内存的 RAII owner／自定义删除器管理插件资源，借用参数保持裸指针或已有借用类型。分配失败通过既有错误码返回；禁用异常时不能依赖 `try/catch`，也不能认为加上 `noexcept` 就能把抛异常的分配转换成错误码。使用支持显式失败返回的分配路径，并检查每一步结果。

3. **补全整数与输出契约。** 明确长度单位是字节还是元素，以及空指针在零长度时是否合法。未提供接口原型，不能假定现有 `int`、`long` 的位宽；应按已发布 ABI 写明各目标平台的宽度、符号和调用约定，保持布局兼容。若长度使用 `size_t`，其宽度随目标平台，32/64 位宿主应匹配对应插件。有符号长度先拒绝负值，宽类型转 `size_t` 前检查 `SIZE_MAX`；分配前检查乘法及加法，例如 `count <= SIZE_MAX / sizeof(T)`，并检查容量、对齐及实际可访问范围。先检查输出参数地址，对有效输出槽设为 `NULL`／`0`；完整成功后一次性发布结果并转移所有权，失败不留下半成品。非法输入返回可恢复错误，不能依赖 `assert`。

4. **准备可观察验证。** 对每一次分配、解析及提前返回逐点注入失败，记录资源编号、分配器身份和分配／释放次数；期望失败后输出为空、插件净存活资源为零、宿主借用内存从未被插件释放。覆盖零长度、负长度、截断转换、乘加溢出、空输出指针、成功转移和配对释放。按接口契约验证重复关闭，并覆盖并发销毁、回调退出与卸载顺序；置空一个句柄不能消除其他悬挂别名。
